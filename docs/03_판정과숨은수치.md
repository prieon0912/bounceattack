# 판정·사거리·그림에 숨어 있는 수치

이 문서는 원본 실행 블록과 원본 이미지 메타데이터를 기준으로 작성했다. 게임 화면의 모양이나 기술 설명만 보고 사거리를 정하지 않았다. 코드로 바로 정해지는 중심거리 문턱과, 이미지·피벗·궤적을 합쳐 계산하는 접촉 범위를 구별한다.

## 1. 이 게임에 있는 판정 방식

| 방식 | 실제 규칙 | 이미지 교체의 영향 |
|---|---|---|
| 중심거리 검사 | 두 객체 원점 간 유클리드 거리와 숫자를 비교 | 검사 대상의 원점이 같으면 그림만 바꿔도 거리 문턱은 그대로다. 크기가 커져도 상대 반지름을 자동 가산하지 않는다. |
| 그림 접촉 검사 | 회전·크기·표시 상태가 적용된 스프라이트끼리 접촉 검사 | 그림의 불투명한 모양, 빈 공간, 피벗, 회전, 크기, 표시 여부가 영향을 준다. |
| 경로 다점 검사 | 한 업데이트에 여러 위치로 옮겨 가며 접촉 검사 | 각 위치 간 간격과 검사 시점까지 보존해야 한다. 화면에 그린 선 길이와 실제 피해 검사는 별개다. |
| 상태/신호 기반 피해 | 거리 검사 없이 공통 타격 함수나 다른 메시지에서 적용 | 지속 피해·표식 폭발·벽꿍·파열 등을 발사체 피해와 따로 추적해야 한다. |

공개 엔진에서 `reach_something`은 스프라이트에 대해 픽셀 충돌을 사용한다. 현재 검사 주체가 숨김 상태면 false를 반환하고, 타깃의 보이는 복제본도 순회한다. `distance_something`과는 다르다. 원작의 본체 잔상 복제본을 타깃 목록에서 제외하는 추가 코드가 있는지까지 판정에 포함해야 한다. [공식 접촉 코드](https://github.com/entrylabs/entryjs/blob/develop/src/playground/blocks/block_judgement.js)

## 2. ‘크기 20’이 20% 확대라는 뜻은 아니다

공개 엔진의 크기 S는 `(원본가로×|scaleX| + 원본세로×|scaleY|) / 2`다. 균등 배율이면 표시 가로는 `2×S×가로/(가로+세로)`, 표시 세로는 `2×S×세로/(가로+세로)`다. `setSize`의 최솟값은 1이므로 코드의 0.1은 완전 소멸을 뜻하지 않는다. [공식 크기 코드](https://github.com/entrylabs/entryjs/blob/develop/src/class/entity.js)

따라서 긴 검의 크기 28과 동그란 주먹 크기 28은 가로 길이가 다르다. 모양을 바꾸면 가로·세로가 바뀌며, 크기를 다시 설정하는 순서도 중요하다.

## 3. 회전 중심이 공격 길이를 바꾼다

`regX, regY`는 그림의 어느 지점을 객체의 원점으로 삼는지 정한다. 원점이 손잡이나 그림 바깥에 있으면, 같은 가로 길이여도 본체에서 칼끝까지 더 멀어진다. 모양 전환 시에는 중심으로부터 피벗의 오프셋이 이어진다. 새 그림을 가운데 정렬로 넣으면 현재 검 궤적을 보존할 수 없다.

아래는 **회전 0도, 객체 원점 기준**의 기하값이다. 몸에서 무기 원점까지의 추가 이동과 상대 크기는 아직 더하지 않았다. ‘알파 X 외곽’은 그림의 비어 있지 않은 부분을 감싼 경계이며, 그 안이 전부 타격 가능한 꽉 찬 직사각형이라는 뜻이 아니다. 원본을 알파 0.2 초과로 래스터화해 산출했으므로 엔진의 변환 후 픽셀 샘플링과 경계 1픽셀 정도 차이가 날 수 있다.

| 1P 크기변환 / yxpi | 16.875 | 196×196 | 16.88×16.88 | 98.00, 98.00 | -8.44 ~ 8.44 |

성 미카엘의 검은 원본 가로 367인데 피벗 X가 −45.84로 그림 바깥이다. 크기 28.1에서도 회전 0도 기준 오른쪽 외곽이 객체 원점에서 약 36.65까지 나간다. 반면 글램스의 보통 주먹은 크기 9에서 원점 기준 대략 −4.5~+4.5다. 두 캐릭터의 표시 크기만 비교해서 같은 사거리 보정을 주면 안 된다. 실제 적중 범위는 여기에 본체와 무기 원점의 간격, 현재 회전각, 주먹 전진량, 상대 위치가 합쳐진다.

## 4. 가드는 ‘작은 주먹 히트박스’ 하나로 설명되지 않는다

- 평타 `강화타격`: 준비/모양 전환 후 **한 번** `중심거리(2player)<33`, `상대 은신=0`, `자신 기절=0`에 해당하는 실행 경로를 검사한다. 피해 9, 속박값 0.5. 해당 타격 블록에는 앞/뒤 방향 조건이 없다. 즉 주먹 그림을 키우는 것으로 이 문턱을 늘릴 수 없다.
- 스킬 `분쇄`: 내려찍기 애니메이션 뒤 **한 번** 중심거리 <37을 검사한다. 적중 시 피해8, 에어본, MP30 환급. 실패 분기에는 이동 증가 메시지. 이 역시 주먹 픽셀 크기만 키워서는 해결되지 않는다.
- 궁 `철갑치기`: 주먹 오브젝트의 그림 접촉을 30회 이동 구간 안에서 검사한다. 피해34, 상대 반동 ±300과 자신 반동 ∓97. 이 기술은 주먹 그림·피벗·크기·전진 궤적의 영향을 직접 받는다.

따라서 가드의 맞히기 어려움은 평타/스킬의 거리 문턱, 검사 타이밍, 높이 차, 자기 둔화와 긴 준비 동작을 함께 봐야 한다. ‘그림이 닿는데도 평타가 빗나감’과 ‘궁 주먹의 실제 접촉이 작음’은 서로 다른 원인이다. 중심거리 원형 조건이므로 점프한 상대는 가로로 가까워도 높이 차 때문에 문턱 밖으로 나갈 수 있다.

## 5. 글램스는 형태와 판정이 강하게 결합돼 있다

| 형태 값 | 몸 크기 목표 | 주먹 크기=몸×0.5625 | 받는 피해배율 | 평타 기본 피해 |
|---|---|---|---|---|
| 1·작음 | 10 | 5.625 | 1.5 | 4 |
| 0·보통 | 16 | 9 | 1 | 5 |
| 2·큼 | 30 | 16.875 | 0.66667 | 12 |

몸 크기는 즉시 바뀌지 않고 `(목표−현재)/9`를 반복 더해 수렴한다. 주먹 크기와 X/Y 오프셋은 그때그때의 몸 크기를 읽으므로 변신 중에는 중간 크기·중간 사거리가 된다. 공격 모션의 좌우 상태에도 몸 크기/16 배율이 걸린다. 작은 형태는 피해를 더 받으면서 주먹의 실제 외곽도 작아지는 구조다.

보통 스킬은 보호막17과 5 피해 두 구간, 작은 스킬은 서로 다른 높이 0/4/−4에 펀치 EFF를 생성, 큰 스킬은 14 피해·기절·둔화9다. 작은 펀치 EFF는 크기10이지만 원본 비율 259:99 때문에 표시 외곽은 약14.47×5.53이다. 작은 몸의 손과 EFF의 실제 타격 범위는 서로 다르다.

## 6. 발사체 사거리는 속도×수명 하나로 끝나지 않는다

원작에는 다음이 섞여 있다.

1. 생성 직후 진행 방향으로 이동한 뒤 반복 이동을 시작하는 발사체.
2. 이동 → 충돌 → 한 번 더 이동 → 충돌 순서가 한 반복 안에 들어 있는 발사체.
3. 속도 상태를 매 반복 줄이거나 중력 상태를 따로 바꾸는 투사체.
4. 소유자 위치에서 매번 다시 출발해 오프셋만 더하는 무기.
5. 목표를 향해 각도를 재설정하는 귀환/유도 탄.
6. 그림은 커지지만 최초 명중 피해가 현재 크기에 반비례하는 폭발.
7. 벽에 튕기거나 적에게 박힌 뒤 붙어서 따라가는 발사체.

각 명령과 조건을 순서대로 보존해야 한다. 최대 사거리는 벽·상대·현재 소유자 이동·복제본 삭제·기절 중단에 따라 달라진다. 모든 투사체에 ‘range=100’ 하나를 임의로 부여하지 않았다. 순서가 있는 모든 크기/좌표/회전 명령은 데이터 파일 geometry에 수록했다.

## 7. 코드에서 확인된 설명 차이와 구조상 주의점

| 항목 | 설명 또는 흔한 해석 | 실행 코드 기준 |
|---|---|---|
| 가드 생존 | HP1로 생존 | HP<0일 때 0.01, 보호막+12, 피해배율0 후 240회 뒤1 |
| 성 미카엘 추가 피해 | 기절 대상 추가6 | 기절 해제 후 추가7 |
| 뉴크 스킬 비용 | 분리된 옛 코드에는40 | 시작 이벤트에 연결된 실제 접착제 비용21 |
| 아르테네스 스킬/궁 비용 | 궁이 더 비쌀 것 | 둘 다26 |
| 라이칸 MP | 모든 캐릭터와 같은 자연회복 | 자연 회복 제외, 적중으로 충전, 변신 중 반복 −0.24 |
| 네이션 나무 방어 | 양측 동일할 것 | 1P 피해배율0.75, 2P0.8 |
| 마검사 이동 부스트 복구 | 양측 동일할 것 | 배경 코드의 1P 캐릭터19는 +0.01, 2P 쪽 일반 복구는 +0.03 |
| 피해 함수 두 번째 인자 | 무적/피해 간격 | 타격 표시 변수에 대입하는 값 |
| 화염 궁의 늦은 폭발 | 언제나 피해 | 크기>180까지 늦게 닿으면 `(180−크기)/−5`가 양수가 되는 코드 경로가 있음. 공통 함수에 양수로 전달되면 일반 HP 분기에서는 증가 방향이므로 그대로 피해로 절댓값 처리하면 원작과 다름 |
| 전적 목록 | 34명 전체와 길이가 같을 것 | 픽/승/패 목록은28칸, 캐릭터 기술 설명은35칸(마지막0) |

위 항목을 이번 분석에서 수정하지 않았다. 새 게임에서 보존할지 고칠지는 ‘원작 규칙’과 ‘개선 규칙’으로 나눠 결정해야 한다.

## 8. 이미지 교체를 위한 보존 데이터

- 캐릭터 몸의 피격 모양과 표시 모양을 분리한다.
- 공격의 기준점, 좌우 오프셋, 회전 중심, 회전각, 활성 구간을 기록한다.
- 원작 픽셀 판정을 유지할 기술은 원본 알파 마스크/다각형을 별도로 보관한다. 새 그림 파일을 판정의 유일한 원본으로 삼지 않는다.
- 중심거리 판정은 숫자 문턱과 기준 객체를 보존한다. 원이나 사각형 판정으로 바꿀 때 반지름 합을 새로 더하지 않는다.
- 모양 프레임 변경으로 실제 크기와 피벗이 달라지는 순서를 보존한다.
- 공격 인스턴스마다 소유자·형태·원소·선택 기술·방향·타격 이력을 보관한다.

현재 이미지1510개를 모두 찾아 측정했다. 1505개는 알파 외곽을 산출했고 칼바람 객체의 SVG5개는 viewBox 높이가0이어서 이 렌더러로 외곽을 확정하지 않았다. 그5개도 JSON 메타데이터의 크기와 원본 파일 경로는 보존했다. 이들은 ‘아예 그림이 없다’는 뜻이 아니라 측정 불가 항목으로 구분했다.
