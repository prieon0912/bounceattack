# 바운스어택 웹 이식

34명 캐릭터의 원본 실행 블록을 JavaScript로 변환하고, 독립 Canvas 실행부에서 구동합니다. 엔트리 편집기나 EntryJS 전체 엔진을 내려받지 않습니다. 원본 그림·소리, 피해·소모량·반복 횟수·메시지·패시브·변신 분기는 그대로 포함합니다.

## 실행

Node.js 20 이상에서:

```sh
npm ci
npm run build
npm test
npm start
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 처음에는 `npm ci`로 통신용 라이브러리를 설치합니다. `index.html`을 파일로 직접 열면 브라우저의 자료 접근 제한 때문에 동작하지 않습니다.

- 1P: A/D 이동, W 점프, E 기본 공격, R 스킬, S 궁극기
- 2P: ←/→ 이동, ↑ 점프, O 기본 공격, P 스킬, ↓ 궁극기
- Esc: 일시정지. 다른 창으로 이동하면 자동으로 일시정지합니다.
- 같은 PC에서 하는 로컬 대전과, 방 코드로 연결하는 온라인 1대1 대전을 지원합니다.
- 온라인에서는 각자 자기 캐릭터만 조작합니다. 두 사람 모두 A/D, W, E/R/S를 사용할 수 있고 2P용 방향키·O/P/↓도 같은 동작으로 매핑됩니다.
- 온라인 배포에는 아래의 Redis 연결이 필요합니다. 로컬 실행은 메모리 방 저장소를 사용하므로 설치 없이 두 브라우저로 테스트할 수 있습니다.

## Vercel 배포

1. Vercel에서 **Add New → Project**를 선택하고 `prieon0912/bounceattack` 저장소를 연결합니다.
2. Root Directory는 저장소 루트로 둡니다. `vercel.json`이 아래 설정을 지정하므로 별도 프레임워크를 선택할 필요가 없습니다.
3. **Deploy**를 누릅니다. 이후 연결한 브랜치에 푸시하면 자동 재배포됩니다.

| 설정 | 값 |
| --- | --- |
| Framework Preset | Other (`framework: null`) |
| Build Command | `npm run build` |
| Output Directory | `public` |
| 환경 변수 | 온라인 대전용 `REDIS_URL` 또는 `KV_URL` |

정적 파일을 배포하므로 `npm start`로 서버를 계속 실행할 필요가 없습니다. `source/`와 `tools/`는 빌드에 사용하고 `public/`만 사이트로 공개합니다. HTML·JS·JSON·SVG·PNG·음악 파일의 경로는 그대로 유지합니다.

`regions: ["icn1"]`은 향후 Vercel 서버 함수를 추가할 경우 서울에서 실행하도록 지정합니다. 게임 파일은 Vercel CDN이 제공하며, `/api/online` 서버 함수가 방 연결과 중계를 담당합니다. WebSocket 연결은 최대 300초마다 재연결되며, 브라우저 직접 연결 중에는 계속 서버 함수를 열어 두지 않습니다.

로컬 확인은 기존처럼 `npm start`로 합니다. Vercel CLI를 사용하는 경우 프로젝트 루트에서 `vercel`로 미리보기 배포하고 `vercel --prod`로 운영 배포할 수도 있습니다. Vercel 로그인과 프로젝트 연결이 필요합니다.

## 온라인 대전 연결

1. Vercel 프로젝트에서 **Storage → Create Database / Marketplace**를 열고 Redis 저장소를 연결합니다. 예: Upstash for Redis. 생성 화면에서 무료 플랜을 확인하고 선택합니다.
2. 연결 후 프로젝트의 환경 변수에 `REDIS_URL` 또는 `KV_URL`이 생겼는지 확인합니다. 값은 `redis://` 또는 `rediss://`로 시작하는 **Redis 연결 문자열**이어야 합니다. `https://`로 시작하는 REST URL은 여기에 사용할 수 없습니다. 자동 생성되지 않으면 Redis 제공자 화면에서 연결 문자열을 복사하여 `REDIS_URL`로 등록합니다. 비밀번호가 포함되므로 브라우저 코드나 Git에 넣지 않습니다.
3. Production 환경에 적용한 뒤 **Redeploy**합니다. `/api/online`을 열어 `online: true`가 표시되면 방 서버 설정이 준비된 것입니다.
4. 게임에서 **친구와 온라인 대전 → 캐릭터 선택 → 방 만들기**를 누릅니다. 초대 링크 또는 8자리 방 코드를 친구에게 알려줍니다. 친구도 캐릭터를 고르고 입장한 뒤, 둘 다 **준비 완료**를 누릅니다.

공식 연결 안내: https://vercel.com/docs/marketplace-storage

### 동작 방식

- 캐릭터 선택은 시작 전까지 상대에게 공개하지 않습니다. 현재 중복 캐릭터는 원작의 공유 상태 문제 때문에 차단하며, 두 사람이 같은 캐릭터를 골랐다면 준비를 해제하고 다시 고르도록 안내합니다.
- 방·준비 상태와 연결 정보를 Redis에 보관합니다. 방 코드 유효 기간은 마지막 서버 활동 후 2시간이며, 대전 중에도 주기적으로 갱신합니다.
- 연결할 때는 Vercel WebSocket을 사용합니다. WebRTC 데이터 채널이 연결되면 대전 입력은 브라우저끼리 직접 교환하고, 불필요한 서버 연결을 닫습니다. 직접 연결이 불가능하면 Vercel WebSocket + Redis Pub/Sub 중계로 계속합니다.
- 서버는 전투를 시뮬레이션하지 않습니다. 같은 원본 코드·난수 시드·프레임별 입력으로 양쪽 브라우저가 계산합니다. 입력을 3프레임(60Hz 기준 약 50ms) 앞에 예약하며, 상대 입력이 없으면 결과를 추측하지 않고 기다립니다. **현재는 입력 지연을 사용하는 동기화이며 예측·롤백은 구현하지 않았습니다.**
- 120프레임마다 전투 상태를 비교합니다. 다른 결과가 감지되면 임의로 한쪽 결과를 덮어쓰지 않고 대전을 정지해 다시 준비하도록 합니다.
- 서버 연결이 끊기면 재접속하고 최근 입력 기록을 다시 전달합니다. 탭을 새로고침하면 같은 탭의 임시 접속 정보로 방에 재입장하고 양쪽을 준비 화면으로 돌립니다. 진행 중인 전투를 중간 프레임부터 복원하는 기능은 아닙니다.
- 한쪽이 일시정지하거나 게임 탭을 숨기면 대전을 일시정지합니다. 일시정지한 사람이 계속하기를 눌러야 재개됩니다.
- 인터넷 환경과 브라우저에 따라 직접 연결 성립 여부와 지연이 달라집니다. 실전 핑 및 월 100시간의 무료 사용량은 실제 배포 후 측정해야 합니다. 서버 중계가 자주 사용되면 Redis 명령 수와 Vercel 사용량도 늘어납니다.

### 파일 위치

| 위치 | 역할 |
| --- | --- |
| `api/online.js` | Vercel WebSocket 함수 진입점 |
| `server/rooms.js` | 방·준비·블라인드 선택·접속 권한·공통 시드 |
| `server/store.js` | Redis 저장소와 로컬 전용 메모리 저장소 |
| `server/online-server.js` | 방 이벤트와 입력을 다른 인스턴스까지 중계 |
| `public/src/online.js` | 직접 연결·중계·재연결·입력 전송 |
| `public/src/frame-sync.js` | 프레임 동기화·재전송·상태 비교 |
| `public/data/build.json` | 빌드 호환성 식별자. 빌드 때 자동 생성 |

로컬에서 Redis를 연결해 실제 저장소를 검증하려면 `REDIS_URL` 환경 변수를 설정하고 `npm start`를 실행합니다. 비밀 값은 `.env.example`을 참고하되 Git에 커밋하지 않습니다. 예시 파일은 자동으로 읽지 않으므로 셸이나 실행 환경에서 환경 변수를 설정해야 합니다.

## 수정할 위치

| 위치 | 역할 |
| --- | --- |
| `source/characters/01.json` ~ `34.json` | 캐릭터별 이름, 주요 오브젝트 ID, 명시적 수치 변경 목록 |
| `source/original-project.json` | 원본 블록·모양·변수·메시지의 보존본 |
| `tools/compile-original.cjs` | 블록을 실행 가능한 JS로 변환. 알 수 없는 블록이면 빌드 실패 |
| `public/src/runtime.js` | 시간·복제·변수·입력·그림 크기·충돌 규칙 |
| `public/src/renderer.js` | 화면 표시. 전투 규칙과 분리 |
| `public/src/assets.js` | 이미지 캐시·원본 알파 판정 데이터 |
| `public/src/app.js`, `public/style.css` | 선택 화면·대전 UI |
| `public/assets/` | 원본 그림과 소리. 원본 바이트 검사 대상 |
| `docs/` | 34명 기술 해설과 판정 분석 |

`public/src/original-program.js`는 생성물이므로 직접 수정하지 마세요. 재빌드 시 덮어씁니다.

캐릭터 코드를 보기:

```sh
node tools/inspect-character.mjs 14
```

번호 14는 가드입니다. 원본 블록 ID와 입력값을 읽기 좋은 JSON으로 보여줍니다. 주요 오브젝트 외에 공통 피격 처리, 보조 효과, 상태 관리 오브젝트도 기술에 관여하므로 `docs/` 설명을 함께 보세요.

예: 브랜드의 원본 기본 공격 크기 블록을 명시적으로 지정하려면 `source/characters/01.json`의 `overrides`를 아래처럼 수정합니다. **현재 배포본의 overrides는 전부 빈 배열이며 아무 수치도 바꾸지 않았습니다.**

```json
"overrides": [
  { "objectId": "m9km", "blockId": "vdxq", "parameter": 0, "value": 21 }
]
```

오브젝트 ID와 블록 ID를 함께 사용합니다. 원본에 복사된 블록 ID가 있기 때문입니다. 이 기능은 숫자 리터럴 입력만 바꿀 수 있으며, 수식이나 변수 입력을 실수로 덮어쓰면 빌드를 중단합니다. 1P/2P 양쪽의 해당 블록을 수정해야 대칭으로 바뀝니다. 비용·쿨타임은 주 공격 오브젝트가 아닌 공통 입력 오브젝트에 있을 수 있습니다.

그림 교체는 렌더러와 판정 데이터를 따로 바꾸는 작업으로 진행해야 합니다. 지금 `assets.js`는 원본 그림에서 알파 마스크를 한 번 만들고 재사용합니다. 그림 파일만 바꾸면 원작의 피격 범위도 달라지므로, 다음 단계에서 원본 판정용 마스크를 고정하고 새 그림을 매핑하는 편집 기능을 추가하는 것이 좋습니다. 대체 스킬/궁극기는 현재 추가하지 않았습니다.

## 보존 범위와 검증 한계

- 전투 장면 282개 오브젝트, 이벤트 스레드 863개, 실행 문장 21,036개를 변환했습니다. 분리되어 실행되지 않는 블록은 승격하지 않았으며 목록을 `source/compile-coverage.json`에 남겼습니다.
- 원본 이미지/소리 2,800개 파일은 SHA-256과 크기를 검사합니다. SVG를 읽을 수 없는 경우 같은 원본에 포함된 PNG를 사용합니다. 엔트리의 기본 1×1 빈 그림만 공식 EntryJS 저장소의 동일 리소스를 포함했습니다.
- 원본 내 `start` 소리 하나는 메타데이터만 있고 실제 파일이 없으며 실행 블록에서도 사용하지 않습니다. `source/known-missing-assets.json`에 기록했고 임의의 소리로 대체하지 않았습니다.
- 고정 60Hz, 그림 크기 계산, 중심점, 좌우 반전, 회전, 원본 소수 계산, 복제 시 지역 변수 복사, 메시지와 반복 제어를 재현합니다. 투명도 효과가 100인 물리용 스프라이트도 원작처럼 충돌에 사용합니다.
- 자동 검사는 양쪽 플레이어의 34명 × 기본/스킬/궁극기 = 204가지 실행 경로에 대해 실행 오류가 없는지 검사합니다. 이 검사는 전체 히트박스·피해량의 원작 대비 완전 동등성을 증명하지 않습니다. 브라우저의 SVG 래스터화 및 픽셀 샘플링 때문에 경계 접촉에 차이가 남을 수 있습니다.
- 중복 선택은 현재 차단합니다. 원작의 공유 상태를 유지한 단계에서 이를 허용하면 동일 캐릭터의 상태와 효과가 섞일 수 있습니다. 안전한 중복 대전을 위해서는 소유자별 상태 분리가 추가로 필요합니다.
- 원작의 일반 2인 모드를 제공합니다. 원작의 AI/보스 모드와 원작 선택 화면은 이 웹 UI에서 제공하지 않습니다.

## 최적화

편집기·블록 해석기를 브라우저에 올리는 대신 빌드 때 JS로 변환합니다. 그림은 URL 기준으로 한 번만 읽고 알파 마스크를 공유합니다. 충돌은 변환된 외곽 사각형으로 먼저 제외한 후 실제 알파를 검사하며, 외곽 계산은 위치·크기·중심점·반전·회전이 같을 때만 캐시합니다. 전투 수치와 반복 횟수를 성능 명목으로 줄이지 않았습니다.

## 출처

사용자가 제공한 `바운스어택밸런스패치.ent` 기준. 원본 파일 SHA-256은 `source/provenance.json`, 원본 리소스 해시는 `source/assets-manifest.json`에 있습니다. 이전에 만든 수정 ENT 파일은 사용하지 않았습니다. 원작과 이미지·음악의 권리를 새로 주장하지 않습니다. 배포 시 기존 원작자 및 개별 리소스의 이용 조건을 유지해야 합니다.

숫자 계산용 BigNumber.js 9.1.2는 MIT 라이선스이며 `public/src/vendor/BIGNUMBER-LICENCE.md`에 원문을 포함했습니다. Entry 블록 의미 대조에 사용한 공식 소스는 https://github.com/entrylabs/entryjs 입니다.
